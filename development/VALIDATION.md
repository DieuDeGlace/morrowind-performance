# ESP/Lua preview 2 validation

Validated on 2026-11-09. This revision uses standard OpenMW APIs and ESP records.
It does not require custom combat engine controls or events.

## Engine rollback and shadow preservation

The Windows engine rollback commit is
20646761aace7749da7d855b765d593405ac85c2. Its complete tree equals the published
Preview 10 source 479a8ac51a8989ac8b9927b2e519f51a530dc17a.

The Android engine rollback commit is
12653a8e1c38faa7d9e6983c4885db71c625728b. Its complete tree equals Preview 10
source 7048e55d4c6e869b01c7fa75d116b1701bbe7443.

The rollbacks preserve history and are pushed to the active physics branches.
No combat hooks remain in those engine trees. Equality includes all renderer,
shader and build files, so the previously validated Preview 10 shadow fix is
preserved exactly.

The reused complete Windows package was built from 479a8ac51, with all normal
tools including openmw-launcher.exe and the editor. Its original CI passed
2,400 C++ tests:
https://github.com/DieuDeGlace/morrowind-performance/actions/runs/42585160353

No native recompilation is needed for byte-identical source trees. Android
rerelease packaging retains the Preview 10 engine pin and changes wrapper
installation version/build validation only. APK signature, identity and native
contents are verified separately in the accompanying package report.

## Numerical and Lua behavior validation

Two full runs execute the actual Preview 10 Combat scripts, for Windows API 166
and Android API 129. Each passes **46 test groups and 10,858 direct numerical
comparisons** against the unmodified original MWSE implementation:

- 540 fist combinations across tiers, armor, strength, fatigue and Always Hit.
- 10,240 weapon-family, tier, toggle, fatigue and range combinations.
- Eight creature, werewolf and Blind cases.
- 64 fortified/drained-stat and negative-fatigue weapon cases.
- Four fortified/exhausted fist cases and two guard/bow fatigue cases.

Further checks cover timers, hit-handler chaining, armor/difficulty order,
temporary-state cleanup, malformed content, save/load, skill progression,
camera rounding and both inactive bow-animation timestamp representations.
The controls double rejects fields absent from the standard OpenMW API.
The standard NGCGuard input action also has a shield-block regression.

## Actual Preview 10 Windows gameplay

The startup scenario applies and removes the companion accuracy ability on a
player, an NPC and a creature, checking the real active-effect magnitude.

The final physical scenario runs ordinary attacks and projectile collisions in
the original, unmodified Preview 10 executable, with no custom native controls.
Random vanilla shield blocks are disabled in the private test profile so Lua
guard behavior is isolated. The run has no Lua errors and confirms:

- Four low-skill weapon hits with the ESP accuracy ability, and no misses.
- Four ordinary fist hits, each with one independent health supplement.
- Four native fist misses, each still producing its one scripted health hit.
- Four frontal Lua shield blocks, zero weapon health damage, and shield
  condition falling from 200 to 184.
- Four damaging rear attacks, with zero Lua guard blocks.
- Normal/full bow hits consuming respectively zero and 1.0 bonus; full draw
  causes the expected greater damage.

These are correctness checks, not measurements of combat or shadow frame cost.
Actual Android device gameplay and timing remain untested.

The first physical fixture sampled equipment before its queued equip action
resolved and used a different rear attack position. The corrected fixture
samples after warmup and rotates the defender in the same clear location.
Its clean final run is the pass cited above; earlier failed fixtures are not
counted as passes.

## Reproduce

Use Python 3.12 and Lupa 2.6:

    python -m pip install lupa==2.6
    python development/build_companion.py --check
    python development/tests/run_tests.py --engine-source PATH_TO_ENGINE
    python development/tests/run_matrix.py --windows-source WINDOWS_ENGINE --android-source ANDROID_ENGINE
    python development/package.py

The optional --quick argument to run_tests.py skips the two large numerical
loops and does not replace the full matrix. The packaged Windows scenarios are:

    ./development/integration/run-gameplay.ps1 -PackageDir BUILD -GameData DATA_FILES -Label startup-check
    ./development/integration/run-gameplay.ps1 -PackageDir BUILD -GameData DATA_FILES -Label combat-check -Physical

Each label creates a private profile under development/results/integration.
The runner rejects timeouts, nonzero exits, missing pass markers and Lua errors.
Generated floor geometry is owned by this project; no proprietary game assets
are redistributed. Integration fixtures and MWSE reference sources are excluded
from the runtime ZIP.

## Remaining adaptations

The accuracy ability raises the native formula instead of replacing it.
Hamstring changes Speed; backward full draw scales movement input. Fist health
damage begins at the hit callback rather than the MWSE attack-release event.
Ordinary damage bonuses use an asynchronous actor-event round trip. UI, reload,
exhausted draw cancellation and projectile recovery also have documented
adaptations. See the runtime README. These results are not a blanket 1:1 claim.
